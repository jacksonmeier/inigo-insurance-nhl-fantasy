# Fantasy Hockey League App: Project Spec

A private, season-long fantasy hockey league for 4 friends, with live scoring from the NHL's public stats API. Must run entirely on free tiers.

## 1. League rules

### Roster
- 6 players per team: 3 F (any mix of C, LW, RW), 2 D, 1 G.
- All 6 players score. No bench.
- 1 IR slot per team (see Injuries and IR).
- 4 teams, 24 players drafted in total.

### Draft
- Snake draft, 6 rounds, random order (generated by the app, visible to everyone before the draft).
- Live draft room that works on phones, updates in real time for all 4 users.
- Enforce roster limits so every team ends with exactly 3 F, 2 D, 1 G.
- Optional pick timer (default 2 minutes, configurable). Commissioner can pause, resume, and undo the last pick.

### Scoring
All values live in one config file (e.g. `scoring.config.ts`) so they can be tweaked without code changes elsewhere.

Skaters:
| Stat | Points |
|---|---|
| Goal | 3 |
| Assist | 2 |
| Power play point | 1 |
| Shorthanded point | 1 (bonus) |
| Shot on goal | 0.3 |
| Hit | 0.2 |
| Blocked shot | 0.3 |

Goalies:
| Stat | Points |
|---|---|
| Win | 4 |
| Save | 0.2 |
| Goal against | -1 |
| Shutout | 3 |

- Points only count for games played while the player is on that team's active roster. Store roster history by date so every point is attributed to the right team, even after trades, drops, and IR moves.
- Regular season games only. Ignore preseason and playoffs.

### Season format
- One season-long race. Highest total points at the end of the NHL regular season wins.
- Single leaderboard ranked by total points, updating live.
- Tiebreaker: most total goals scored by the team's players (while rostered).

### Injuries and IR
- Injury status comes from ESPN's public NHL injury data (see Data sources).
- A player is IR-eligible only if ESPN lists him as Out or Injured Reserve. Day-to-Day players are not eligible.
- Moving a player to IR lets the owner add one temporary replacement from free agency at the same position group (F for F, D for D, G for G).
- IR players earn no points. The temporary replacement earns points normally.
- When the IR player is no longer listed as Out or Injured Reserve, the owner gets an alert and has 24 hours to either:
  - Activate him (the temporary replacement is automatically released to free agency), or
  - Keep the replacement and drop the returning player instead (the replacement becomes a permanent roster player).
- If the owner does nothing within 24 hours, the app activates the player and releases the replacement automatically.
- If the IR slot is full, any other injured player stays on the active roster (earning zero) unless the owner drops someone.

### Free agency and waivers
- All undrafted players are free agents and can be added instantly, first-come, first-served.
- Players dropped by a team go on waivers for 24 hours. During that window, any owner can place a claim. When the window closes, the claim from the owner lowest on the leaderboard wins.
- Every add must keep the roster valid (3 F, 2 D, 1 G, plus the IR slot).

### Trades
- Any owner can propose a trade to another owner. Once accepted, the trade goes through automatically unless another owner vetoes within 24 hours.
- Trades must leave both rosters valid.

### Commissioner
- The league creator is commissioner and can: run and control the draft, fix ESPN to NHL player ID mismatches, manually correct a roster or a point total, and force-process a stuck IR, waiver, or trade.
- All commissioner actions are logged and visible to everyone.

## 2. Architecture

Everything must stay on free tiers.

### Frontend: GitHub Pages
- Vite + React + TypeScript.
- Use hash-based routing (or the 404.html redirect trick) so deep links work on GitHub Pages.
- Mobile-first design. Most use will be on phones during games.
- GitHub Actions workflow deploys to Pages on every push to `main`.
- The repo is public, so no secrets in code. Only the Supabase URL and anon (public) key are in the frontend, loaded from environment variables at build time.

### Backend: Supabase (free plan)
- Postgres database.
- Supabase Auth for the 4 users (email magic link is simplest).
- Supabase Realtime to push point changes, draft picks, and roster moves to every open screen instantly.
- Edge Functions for all calls to the NHL API and ESPN (browsers never call those APIs directly).
- Supabase Cron to schedule the Edge Functions.
- Row-level security on every table: users can only change their own team, only server-side functions can write stats and points, and nobody can edit points from the frontend.
- The service role key is only ever stored as an Edge Function secret.

### Free tier notes
- Supabase free projects pause after 7 days of inactivity. This only matters in the offseason. Document how to restore.
- Supabase free has no backups: add a weekly GitHub Actions job that exports the database (the connection string is stored as a GitHub Actions secret) and commits or uploads the dump somewhere private. Since the repo is public, do not commit the dump to the public repo; use a private repo or GitHub Actions artifacts.

## 3. Data sources

### NHL API (unofficial, undocumented)
- Base: `https://api-web.nhle.com/v1/`
- Community reference: https://github.com/Zmalski/NHL-API-Reference
- Likely endpoints: daily schedule, game boxscore, play-by-play, live scores, team rosters, player landing pages. Verify each against the reference before relying on it.
- Wrap all NHL calls in a single module so any API change only needs fixing in one place.
- Check which fields the boxscore actually provides. Power play points and shorthanded points may need to be derived from play-by-play data if assists are not split out by strength.

### ESPN injuries (unofficial, undocumented)
- Use ESPN's public site API for NHL injuries (verify the current endpoint).
- Wrap in its own module.
- ESPN and the NHL use different player IDs. Build a mapping table matched by name, team, and position, flag low-confidence matches, and let the commissioner fix mismatches manually.

## 4. Scheduled jobs (Supabase Cron)

| Job | When | What it does |
|---|---|---|
| Live scoring | Every 30 seconds | Exits immediately if no games are in progress. Otherwise pulls live data for in-progress games, recalculates points for rostered players, writes changes (Realtime pushes them to clients). |
| Final stats and corrections | Nightly, after all games end | Re-pulls final boxscores for the day (and the previous day) to catch NHL stat corrections, then recalculates. |
| Injury check | Every 1 to 2 hours on game days, plus shortly before the first puck drop | Pulls ESPN injury data, updates statuses, sends IR eligibility and return-to-health alerts. |
| IR, waiver, and trade processing | Every 15 minutes | Resolves expired 24-hour windows (IR activations, waiver claims, trade vetoes). |
| Player import | Daily | Syncs NHL rosters so new call-ups and trades between NHL teams are reflected. |

## 5. Screens

- **Leaderboard (home):** live team totals, today's points per team, a "top scorer of the week" callout.
- **Team page:** roster with each player's season points, today's points, next game, and injury status badge; IR slot; recent transactions.
- **Player search / free agents:** filter by F, D, G; sort by fantasy points; add, drop, claim.
- **Draft room:** draft order, pick timer, available players, each team's picks so far.
- **Trades:** propose, accept, reject, veto.
- **League activity feed:** every add, drop, trade, IR move, and commissioner action.
- **Commissioner tools.**

Alerts (in-app at minimum; push or email optional if free): your player became IR-eligible, your IR player is healthy, a trade needs a response, a waiver claim was processed.

## 6. Build order

Work through these phases in order. Stop after each phase so I can review and test before moving on.

1. **Setup:** repo structure, Vite app, Supabase project, database schema (players, teams, rosters, roster history, games, player game stats, points, transactions, injuries, ID mapping, draft), RLS policies, GitHub Pages deploy workflow.
2. **NHL data import:** player and roster sync, schedule import, boxscore import.
3. **Scoring engine:** pure, fully unit-tested functions. Verify against at least one real past game by calculating a few players by hand.
4. **Live scoring:** Edge Function plus 30-second Cron, Realtime updates to the frontend. Test during a real live game.
5. **Roster history:** points attributed by date to whichever team rostered the player.
6. **Injury module:** ESPN import, ID mapping, status display, alerts.
7. **Draft room.**
8. **Leaderboard and team pages.**
9. **Transactions:** free agency, waivers, trades with veto window, IR slot with temporary replacements and the 24-hour activation window.
10. **Backups and polish:** weekly backup job, commissioner tools, activity feed, README with setup and offseason restore steps.

## 7. Ground rules for building

- Keep it simple. This is for 4 people, not thousands.
- Everything must stay free. Flag anything that would cost money before adding it.
- Ask before making product decisions not covered in this spec.
- Keep scoring values and league settings in config, not scattered through the code.
- Write tests for the scoring engine and the transaction rules (IR, waivers, trades), since those are where bugs will cause arguments.
